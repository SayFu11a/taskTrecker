# Возвращение в профессию — трекер

Одностраничный трекер по плану возвращения во frontend: учёба, собеседования, поиск работы
и тренировки с уровнями **минимум / норма / максимум**.

## Что внутри

- **Плашка «Сейчас»** — показывает текущее время, день недели и что делать прямо сейчас:
  название блока, интервал, сколько минут осталось, что дальше. Тут же — тренировка на сегодня
  (Пн A · Ср B · Пт A, на чётных неделях порядок меняется) и кнопка «Отметить», которая сразу
  пишет уровень в чек-лист. Обновляется раз в 30 секунд и при возврате во вкладку.
- **День** — чек-лист из 7 блоков (Ulbi TV, собеседования, LeetCode, hh.ru, новости Frontend,
  повторение/проект, физическая активность). Каждый блок отмечается уровнем: минимум, норма, максимум.
  Переключатель режима дня: плохой / обычный / хороший. Отдельный план «Плохой день» на 50 минут.
- **Расписание** — два вида, переключаются: «Детально» (15 интервалов от 09:00 до 23:00)
  и «Крупно» (8 больших блоков). Выбор запоминается. Текущий интервал подсвечен.
- **Неделя** — 7 дней с темами (JS, React, TS, браузер, практика, контрольный день, выходной)
  и этапы выхода на 7–8 часов за 8 недель.
- **Тренировки** — программа A/B на турнике и своём весе, подходы и повторения для каждой из
  8 недель, отметки тренировок, путь к первому подтягиванию, восстановление.
- **Прогресс** — серия дней, статистика за 30 дней, heatmap за 5 недель, какие блоки проседают,
  журнал LeetCode.
- **Правила** — 8 правил, которые не дают плану развалиться, и источники по Frontend.
- **Награды** — 14 достижений (первый день, серия 7 дней, тренировки, LeetCode, все блоки за день),
  звуки на действия через Web Audio (без аудиофайлов), аккаунт и уведомления.
- **Офлайн и установка** — `manifest.json` + `sw.js`: сайт ставится на главный экран,
  открывается без адресной строки и работает без сети.

## Запуск

Сайт статический, без сборки и зависимостей. Достаточно открыть `index.html`
или поднять любой статический сервер:

```bash
python3 -m http.server 8100
```

## Деплой

Сайт задеплоен на Vercel: **https://profession-tracker.vercel.app**

Настройки сборки зафиксированы в `vercel.json` в корне репозитория, чтобы проект
не зависел от того, что вручную выставлено в дашборде Vercel:

```json
{
  "framework": null,
  "buildCommand": null,
  "installCommand": null,
  "outputDirectory": "."
}
```

- `framework: null` — отключает пресет фреймворка, репозиторий считается обычной статикой;
- `buildCommand` / `installCommand: null` — шагов установки и сборки нет (нет `package.json`);
- `outputDirectory: "."` — публикуется корень репозитория, где лежит `index.html`.

Значения из `vercel.json` переопределяют Project Settings, поэтому проект собирается
одинаково после переимпорта или в форке. Только строки или `null`: `false` Vercel
отклоняет с ошибкой схемы. Без `outputDirectory: "."` сборка падает с
`STATIC_BUILD_NO_OUT_DIR`, потому что Vercel ищет папку `public/`.

## Установка на телефон

**iPhone:** открыть сайт в Safari → «Поделиться» → **«На экран Домой»**. После этого запускать
трекер с иконки — так он открывается в полный экран, работает офлайн и **только так** на iOS
становятся доступны push-уведомления (ограничение Apple, обойти нельзя).

**Android:** Chrome → меню → «Установить приложение».

## Звуки

Синтезируются через Web Audio API в `sound.js` — аудиофайлов в проекте нет.
Наборы: отметка уровня, день закрыт, тренировка, запись в LeetCode, новое достижение.
Включаются и выключаются на вкладке «Награды» → «Звук», выбор запоминается.
Первый звук «прогревается» на первом тапе — этого требует iOS.

## Аккаунт и синхронизация (Supabase)

По умолчанию всё лежит только в браузере. Чтобы видеть одни и те же отметки с телефона и с ПК,
нужен бесплатный проект Supabase. **Код уже готов, нужно вписать два ключа.**

### 1. Создать проект

1. [supabase.com](https://supabase.com) → **New project**. Регион — ближайший (например, Frankfurt).
2. Дождаться создания (~2 минуты).

### 2. Создать таблицы

1. В проекте: **SQL Editor** → **New query**.
2. Вставить целиком содержимое `supabase/schema.sql` → **Run**.

Создадутся таблицы `days`, `settings`, `push_subscriptions`, включится Row Level Security
(каждый пользователь видит только свои строки) и триггеры `updated_at`.

### 3. Включить вход через Google

1. **Authentication → Providers → Google** → включить.
2. Нужны `Client ID` и `Client Secret` из Google:
   [console.cloud.google.com](https://console.cloud.google.com) → создать проект →
   **APIs & Services → Credentials → Create credentials → OAuth client ID → Web application**.
3. В Google в поле **Authorized redirect URIs** добавить адрес вида
   `https://<project-ref>.supabase.co/auth/v1/callback` (точный адрес Supabase показывает
   прямо в настройках провайдера — скопировать оттуда).
4. Вставить ключи в Supabase → сохранить.

### 3.1. Указать адрес возврата — без этого вход молча ломается

**Authentication → URL Configuration**:

- `Site URL` → `https://profession-tracker.vercel.app`
- `Redirect URLs` → добавить `https://profession-tracker.vercel.app/**`

Это самый частый провал. По умолчанию `Site URL` = `http://localhost:3000`,
и после успешного входа в Google человека выбрасывает на localhost, где ничего
не открыто. Снаружи это выглядит как «кнопка нажалась и ничего не произошло».

Если адрес возврата не разрешён, теперь видно причину: на экране аккаунта
появляется текст ошибки, а не тишина.

### 4. Вписать ключи в код

**Project Settings → API** → скопировать `Project URL` и `anon public` key:

```js
// sync.js
const SUPABASE_URL = "https://xxxxxxxx.supabase.co";
const SUPABASE_ANON_KEY = "eyJhbGciOi...";
```

`anon` ключ публичный, его можно держать в коде — доступ к данным закрывает RLS.
`service_role` в код класть **нельзя**.

Ещё один адрес живёт в самом коде — `APP_URL` в начале `sync.js`. Он должен
совпадать с `Site URL`. Если сайт переедет на другой домен, менять в двух местах:

```js
const APP_URL = "https://profession-tracker.vercel.app/";
```

### Обновления и кэш

Код (`html`, `js`, `css`, `json`) service worker всегда тянет из сети, а кэш держит
только как офлайн-подстраховку — поэтому правки доезжают до телефона при обычной
перезагрузке. Картинки берутся из кэша.

Если правился сам `sw.js`, номер `VERSION` в нём нужно поднять: старый воркер
живёт в браузере отдельно от страницы и не заменяется сам по себе.
При первом входе с уже накопленными локальными данными сайт предложит загрузить их в аккаунт.

### Как устроена синхронизация

- Каждый день — отдельная строка `days(user_id, date, blocks, mode, updated_at)`.
  Поэтому правки с телефона и с ПК по разным дням не конфликтуют.
- `state.meta[date]` хранит локальное время изменения; при расхождении побеждает более свежее.
- Изменения уходят на сервер с задержкой 1.2 с (не дёргаем базу на каждый клик).
- Если сети нет — всё пишется локально, при появлении связи досылается (событие `online`).
- При возврате во вкладку подтягиваются изменения с других устройств.

### Важно про бесплатный тариф

500 MB базы, 50 000 активных пользователей в месяц, неограниченные запросы, карта не нужна.
**Проект засыпает после 7 дней без запросов** — будится кнопкой в дашборде, данные не теряются.

## Уведомления (push)

Работают только когда вписаны Supabase-ключи и VAPID-ключ. Ограничения платформ:

| | Android (Chrome) | iPhone (Safari) |
| --- | --- | --- |
| Условие | любое | **только установленный на экран «Домой»** сайт, iOS 16.4+ |
| Разрешение | по кнопке | по кнопке, автоматически нельзя |
| Свой звук | нельзя | нельзя (играет системный) |

### Настройка

1. Сгенерировать VAPID-ключи: в терминале `npx web-push generate-vapid-keys`.
2. Публичный ключ вписать в `push.js`:

```js
const VAPID_PUBLIC_KEY = "BPxxxxxxxx...";
```

3. Закрытые ключи сохранить как секреты Supabase:

```bash
supabase secrets set VAPID_PUBLIC_KEY=... VAPID_PRIVATE_KEY=... VAPID_SUBJECT=mailto:you@example.com
```

4. Задеплоить функцию напоминаний:

```bash
supabase functions deploy send-reminders --no-verify-jwt
```

5. В расписании Supabase (Edge Functions → Schedules) поставить запуск раз в 15 минут:
   `*/15 6-20 * * *`.

Функция `supabase/functions/send-reminders/index.ts` сверяет время с интервалами из `data.js`
и шлёт push только в подходящий блок, пропуская воскресенье. Часовой пояс — `TZ_OFFSET_MIN`
в начале файла (по умолчанию UTC+3).

## Данные

Все отметки хранятся в `localStorage` браузера (ключ `vp-tracker-v1`). Бэкенда нет.
Сбросить всё можно на вкладке «Прогресс» → «Сбросить всё».

## Файлы

| Файл | Назначение |
| --- | --- |
| `index.html` | разметка страницы |
| `styles.css` | оформление, тёмная тема, адаптив |
| `data.js` | весь контент плана: блоки, расписание (детальное и крупное), неделя, тренировки, правила |
| `app.js` | логика: отметки, «Сейчас», статистика, рендер |
| `sound.js` | звуки достижений через Web Audio (без файлов) |
| `achievements.js` | 14 достижений и их проверка |
| `sync.js` | вход через Google, синхронизация с Supabase |
| `push.js` | подписка на уведомления, инструкция для iOS |
| `sw.js` | service worker: офлайн-кэш и приём push |
| `manifest.json` | установка на главный экран |
| `supabase/schema.sql` | таблицы, RLS-политики, триггеры |
| `supabase/functions/` | Edge Function для напоминаний |

Контент правится в `data.js` — структура отделена от кода.
